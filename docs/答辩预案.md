## Q1. 你们为什么设计了三个数据源（仿真 / 回放 / 真机）？这样设计的价值是什么？

**答**：园区巡检有三个现实阶段——真机没到位时开发没法做、真机跑过的数据没有沉淀、真机接入时协议要重新写。我们用**一套统一巡检协议**（patrol / recheck / handle / stop 等命令与事件，见 `src/core/protocol.js`）把三种数据源统一掉：

- **仿真引擎**：前端内置、零依赖，真机没到位就能开发调试和演示，且异常真值可控（seed=2026），方便自动化测试断言；
- **历史回放**：省赛实测记录可复盘、可给评审看真实运行证据；
- **真机接入**：WebSocket 设备协议即插即用，附带模拟设备脚本可联调。

价值有三点：**开发不被硬件卡住**（三适配器切换只需改一个配置）、**演示永不掉线**（断网也全流程可演）、**扩展即插即用**（新设备只要实现同一套协议）。这也是我们把它放在架构图正中间的原因。

**⚠️ 追问「适配器具体怎么切」**：`composables/useDataSource.js` 统一接入层，上层视图只依赖协议接口，适配器内部各自实现推进逻辑，切换数据源对页面零改动。

## Q2. AI 识别为什么不本地部署模型，而走云端 API？

**答**：这是权衡后的工程决策，理由三条：

1. **场景匹配**：巡检识别是低频调用（一次巡逻触发个位数次判读），不是高频实时流，云端 API 的延迟完全可接受（我们做了 90 秒超时对齐）；
2. **部署现实**：园区侧设备（巡逻车 AGV / 工控机）算力有限，本地跑多模态大模型需要千元级 GPU，硬件成本远超本项目定位；而 OpenAI 兼容接口让园区可以**自由选择任意厂商模型**，不锁定供应商；
3. **工程可控**：我们把 AI 设计为「可解释、可控、可降级」——识别结果带把握程度和证据描述（可解释），提示词工程控制误报（可控），模型不可用时助手自动降级本地规则（可降级），**AI 融入流程而不是外挂于流程，AI 挂了平台照样能转**。

**⚠️ 追问「那离线怎么办」**：前端核心功能（仿真巡逻/回放/工单/工作台）不依赖后端开箱即用；AI 助手离线自动降级本地规则引擎，演示永不掉线。

## Q3. 和市面上的园区巡检产品（传统安防平台）相比，你们的差异在哪？

**答**：传统安防平台是「**摄像头 + 人盯屏幕**」，问题在于异常发现靠人、处置流转靠微信群、巡检结果没有沉淀。智巡的差异在三点：

1. **发现→处置→报告全流程闭环**：异常自动派单（pending → processing → resolved），可重开返工、全程留痕，最后一键导出 PDF 巡检报告归档——很多产品只做到"发现"就结束了；
2. **虚实结合**：三数据源统一协议，一套平台覆盖演示推演、历史复盘、真机接入三个阶段，这是我们在同类作品中很少见到的架构完整度；
3. **AI Agent 化的交互**：普通话下指令即可操作平台（"详查西南分区""导出报告"），动作经白名单执行保证安全，而不是让用户在菜单里找功能。

## Q4. AI 识别的误报怎么控制？识别结果可信吗？

**答**：三道防线，全部经过真实回归验证（见测试报告第三节）：

1. **提示词工程**：判定范围限定在巡检异常类型（垃圾分类违规/未熄烟头/植被缺水等），对正常设施做豁免规则——例如路侧交通锥是合法设施，初版曾误报"通道占用"，加豁免规则后两帧干净画面**零误报**；
2. **证据链可追溯**：每条异常带把握程度、证据描述、证据照片，复核状态机（初步判断 → 无人机复核中 → 已复核确认）把 AI 判读和人工确认分开，AI 只做初筛不做终审；
3. **出口净化**：模型偶发把画面水印文字带进证据描述，服务端出口统一剥离杂讯字样，保证报告文案干净。

另外针对推理型模型（先思考后作答）做了兼容修复：token 预算放宽 + reasoning_content 兜底解析，3 次真实识别调用全部成功。

## Q5. 前端用了什么技术？地图是拿什么做的？

**答**：Vue 3（Composition API）+ Vite + Element Plus。园区地图是**自研 Canvas 2.5D 渲染**（`ParkMap.vue`）：伪等距视角、分区/设备/路线的绘制与交互、巡逻车动画都在 Canvas 上实现，没有用任何重型 GIS 库——这也是首屏体积能做到 gzip 约 200KB 的原因之一。地图工作台支持拖拽自建场地（分区/设备/停靠点/路线），保存即用，所以叫"任意场地可建图"。

## Q7. 首屏加载性能怎么样？做了哪些优化？

**答**：两层优化，实测数据：

1. **慢网占位**：品牌化开屏页兜底冷启动，避免首屏白屏；
2. **构建体积优化**：Element Plus 组件按需打包 + 构建产物分析，**JS 主包从 1.1MB 压到 428KB（gzip 传输 352KB → 146KB），首屏传输体积近乎减半**；样式保持全量引入以保证暗色主题覆盖的稳定性。每次构建后跑生产包冒烟（5 项断言）防回归。

**⚠️ 追问「为什么样式不按需」**：CSS gzip 后只有约 54KB，按需收益小；而我们的暗色主题是 CSS 变量覆盖实现，全量样式是零风险的稳定选择——性能优化以不引入风险为前提。

## Q8. 数据安全和隐私怎么考虑的？

**答**：三条边界：

1. **模型 Key 不出机**：API Key 只保存在本机 `server/config.local.json`（已加入 .gitignore，严禁提交），仓库里只有 example 模板；页面配置保存前自动试连校验、回显打码；
2. **照片不出本机**：巡检照片传到本地后端，由后端调用模型 API 判读，平台自身不存储、不上传第三方；
3. **报告不外泄**：PDF 报告在本地生成，模型 Key 明确不随报告外发。

## Q9. 真机接入的协议具体是什么样的？扩展新设备难吗？

**答**：WebSocket 设备协议（`docs/device-protocol.md` 有完整文档）：平台下发命令（巡逻/拍照/急停），设备回传事件流（状态、异常、证据帧）。配套 `server/sim_device.py` 模拟真机可本地联调，我们真机模式的全部测试都是先在模拟设备上验证协议、再接真实硬件。扩展新设备（如无人机）只需实现同一套协议的适配器，上层视图零改动——这是 Q1 统一协议设计的直接收益。

## Q10. 你们的助手是 Agent 吗？工具调用是怎么实现的？

**答**：是标准 Agent 模式。小巡接收自然语言后，由大模型做意图解析并产出结构化动作（Function Calling 模式），平台侧维护一个动作白名单（巡逻 / 切换场景与数据源 / 查询 / 派单处置 / 导报告 / 呼叫复核），只有白名单内的动作才会被执行——模型只负责"决策"，执行权在平台，既灵活又安全。每个动作下发前都会经过状态校验（比如任务进行中不重复发起巡逻）。

## Q11. 听说你们做了 RAG 检索增强，具体是怎么实现的？

**答**：我们把园区巡检的领域知识做成了本地知识库（处置 SOP、判定标准、平台指南三份 Markdown），助手回答"怎么处置""规范是什么"这类知识型问题时，先用 BM25 检索相关知识片段注入提示词，再由大模型组织回答，回答来源可标注（sources 字段）。

技术选型上有个亮点：**零外部依赖**——中文场景我们用字符级 bigram + BM25（经典信息检索算法）替代向量数据库和嵌入模型，不需要额外付费 API、不引入新依赖，检索效果经测试完全够用（知识类问题精准命中、闲聊类零误触），并把"检索不误触"写进了自动化测试（test_rag.py 8/8）。

实测效果：问"垃圾分类违规怎么处置"，回答会完整引用 SOP 的处置步骤（拍照取证→通知保洁 15 分钟到场→30 分钟时限→大件垃圾 2 小时清运→危险废弃物单独收运），且标注来源。

**⚠️ 追问「为什么不用向量数据库」**：知识库只有三份文档、十六个知识块，BM25 在这个量级效果足够且零成本；架构上检索器是独立模块，未来知识量大了可以平滑换成向量方案。

## Q12. 助手的回答是流式的吗？怎么实现的？

**答**：是。后端提供 SSE 流式端点，用 OpenAI 兼容的 stream 模式逐段转发，前端逐字渲染带打字光标，用户在模型生成的同时就能看到内容——实测一次知识型问答 1.4 秒内完成、105 个增量片段逐字下发。

工程上有两个兼容设计：一是动作信息用行协议（ACTIONS: 行）随流携带，正文与动作分离传输；二是做了旧协议兼容层（模型若输出旧 JSON 格式，发 reset 帧让前端无缝替换），测试覆盖了标记跨 chunk 截断等边界情况。

## Q13. 项目下一步怎么做？有商业化设想吗？

**答**：短期迭代四个方向（技术文档"展望"已埋点）：

1. **多设备类型接入**：摄像头定点接入 + 无人机巡航适配器，实现地空协同巡检；
2. **工单通知集成**：对接企业微信/钉钉机器人，异常派单实时推送处置人——补上"发现后主动找人"的一环；
3. **多园区集中管理**：场景库云端化，一个账号管理多个园区站点；
4. **移动端值守**：响应式布局延伸到手机，管理者手机上就能派单处置。

商业逻辑是成立的：园区巡检是刚需高频场景，我们平台轻（纯静态+薄后端）、部署门槛低、AI 按需付费，适合物业/园区运营方按站点订阅。
